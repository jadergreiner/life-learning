# Piloto adaptativo — protocolo

**Situação:** desenho aprovado para experimentar; não substitui a cadência de oito posições.

1. Diagnosticar sem consulta Spark, SQL/modelagem, confiabilidade de pipelines e System Design.
2. Separar evidências observadas de hipóteses; ausência de evidência = N0.
3. Selecionar até duas competências de aprofundamento com base em lacuna, relevância, pré-requisitos, aplicabilidade e custo de oportunidade.
4. Para cada atividade explicar motivo, evidência esperada e condição de saída; adaptar duração/escopo ao tempo disponível.
5. Usar Recall para revisão e recuperação; reavaliar prática, diagnóstico, comunicação e transferência independentemente.
6. Revisar resultados e discordâncias do conselho.
7. Alterar cadência/schema apenas após decisão explícita e gravação/validação no Notion.

As durações de 25/50/100 min são alternativas exploratórias, não alterações do padrão operacional. Não iniciar nem encerrar sessões fictícias.
